## Static base URL and metadata search

Mount **`content/`** at a configurable directory URL, for example
`https://example.test/archive/cd1/1988-02/`. Start with `manifest.json`, then load
document paths from its identity/kind records. Resolve every document, preview,
and media asset against the same package base, including deeply nested paths.
Do not resolve them relative to an article document or the application's route.

```js
const root = new URL(baseURL.endsWith('/') ? baseURL : baseURL + '/', document.baseURI);
const manifestURL = new URL('manifest.json', root);
const articleURL = new URL(articleDocument.path, root);
const mediaURL = mediaItem.asset ? new URL(mediaItem.asset.path, root) : null;
```

`catalog.json` supplies navigation and metadata search fields: **title, byline,
issue_id**. This package has no full-text search index. The issue document provides
the full ordered TOC and unmatched entries. A consumer should retain unavailable
media placeholders at their source positions. No deployment origin, filesystem
path, or access-control decision is embedded in runtime documents.

The tests fetch every runtime file under two different nested HTTP base URLs and
compare exact bytes/hashes. The standalone validator requires only the package,
schema, and validator dependencies; it does not need the original disc or RTF.
