## Reproduce and inspect

```sh
python3 -m tools.map_cd1_images
```

Requires the step 5b recovery, step 5c block map, preserved extraction manifest
and raw resources, plus `convert`, `inkscape`, `fc-match`, and Pillow (included
in `requirements.txt`). This run used ImageMagick **7.1.2-18**, Inkscape **1.4.3**,
and Pillow **12.1.1**; exact version output and conversion commands are retained
in the private map. No converter is invoked on the original files in-place.

Outputs under ignored `build/cd1-images/8802065/`:

| Output | Purpose |
| --- | --- |
| `images.json` | Ordered occurrences, source hashes/formats/dimensions, block/caption links, converter logs/versions, derivative hashes, font resolution, and exceptions |
| `assets/*.png` | Nine BMP/DIB conversions at original pixel dimensions |
| `assets/*.svg` | Twelve Inkscape WMF conversions, including the two flagged results |
| `previews/*.png` | White-background SVG inspection renders at 384 dpi; not original-resolution bitmaps |
| `review.html` | Local review page showing resources and warnings in article order |
| `provenance.json` | Compact metadata summary, also tracked without article/media content |

Open `review.html` locally. Review derivatives are separate from the unchanged
Markdown preview and semantic block map; the later reading-room package will
combine the layers. The original resource names and every occurrence remain
traceable, even where several files have identical content.

The command checks input hashes and verifies each source against the extraction
manifest before conversion. It builds in a temporary directory, compares results
with the [tracked summary](../data/catalog/image-maps/cd1-8802065.json), then
replaces generated files individually. Rerun after an interrupted write.
`--write-record` deliberately updates the summary after review; tool/font changes
may change output bytes and require reinspection. Repeated runs in this environment
produced identical outputs. Detailed commands use canonical output paths in place
of temporary staging paths.

Conversion commands follow these patterns:

```sh
convert INPUT -strip -define png:exclude-chunks=date,time OUTPUT.png
inkscape INPUT.wmf --export-type=svg --export-plain-svg --export-filename=OUTPUT.svg
inkscape OUTPUT.svg --export-type=png --export-dpi=384 \
  --export-background=white --export-background-opacity=1 --export-filename=PREVIEW.png
```

The PNG inspection preview is subsequently stripped of generated metadata with
`convert`; decoded pixels are checked again. SVG text stays as text, so local
font availability matters. The current `Times New Roman` lookup resolves to
Liberation Serif, recorded in `images.json`; this is not a claim of font fidelity.

## Findings from visual inspection

**21 occurrences reference 21 names, with 16 distinct source hashes:** one BMP,
eight DIB-named files, and twelve WMFs. All source hashes match the extraction
manifest. The eight `.dib` files here include BMP file headers and are recognized
as BMP by Pillow. All nine bitmap conversions preserve dimensions and decoded
RGBA pixels exactly when checked independently with Pillow.

| Resources | Observation / remaining decision |
| --- | --- |
| `bm43.bmp` | Small section badge in the title. Keep its source context; CD navigation behavior need not be investigated for content preparation. |
| Eight `.dib` resources | Diagrams, formatted example output, and two table images render legibly. Cells/text remain image content, not transcribed or inferred table data. |
| `bm44`, `bm45`, `bm47`, `bm49`, `bm51`, `bm53` (`.wmf`) | Six byte-identical pointing-hand graphics embedded in the Figure 6 example. Keep all six positions, not one collapsed occurrence. |
| `bm46`, `bm48`, `bm50`, `bm52` (`.wmf`) | Overlined numerals 2–5 interleaved with the example text. Retain as media; correspondence with printed content remains unverified. |
| `bm54.wmf` | SVG contains definitions but no drawing elements; its PNG is entirely white. Keep the object and its unresolved attachment. Whether it should display content is not yet established. |
| `bm55.wmf` | Figure 11's equation renders with damaged mathematical glyphs. This derivative is marked `needs_review`, not faithful content. |

The equation's source bytes include a `Symbol` font name, while the generated
SVG uses only `Times New Roman`. Its summation/infinity positions display `å`
and `¥`; the nearby recovered equation source includes `sum` and `inf`.
This is a concrete conversion defect to investigate, not a reason to rewrite
the preserved WMF or automatically substitute characters in the article.

A separate `wmf2svg --inline` experiment on `bm55.wmf` did not solve it: the
result contained invalid character-encoding bytes and rendered replacement
glyphs when opened by Inkscape. That probe remains under
`build/cd1-image-probe/8802065/`, outside the accepted derivative paths. Its exit
status alone did not indicate faithful output. No fallback was silently selected.

The map therefore records **19 `converted_pending_viewer` resources and two
`needs_review` resources**. Five text-bearing SVGs also carry a font-dependence
note. These status names and false `viewer_compared` flags record the earlier
conversion run; they do not impose an original-viewer comparison requirement.
Physical-magazine verification is a separate pending task. Visual inspection
used private contact sheets; the final generated PNGs were checked pixel-for-pixel
against the inspected images.
